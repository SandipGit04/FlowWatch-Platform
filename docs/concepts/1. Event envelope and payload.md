# Event Envelope & Payload

**What problem does this solve?**

Without a standard envelope, the ingestion pipeline would need different code for every
event type. 8 events would mean 8 rules, and adding a 9th event would mean rewriting
ingestion. With one standard envelope, ingestion reads only the outside fields, which are
always in the same place, so it works for any event type without changes. It ignores the
payload not because it can't read it, but because it doesn't need to.

**What confused me at first:**

I didn't know anything about the envelope, payload, or ingestion pipeline. At first I
thought every event shares a single envelope and they are all inside it. The words
"payload" and "ingestion pipeline" were unfamiliar to me.

**What made it click:**

1. **Envelope** — the post office story. A postman can only see the information on the
   outside of the envelope. The events envelope works the same way. The outside carries
   information about each event, like `event_id`, `event_type`, and `event_time`.

2. **Payload** — nothing but the detailed information about the event. In the letter
   story, the letter inside could be a government bill, an electricity complaint, or a
   love letter — completely different contents, but the same envelope structure outside.

3. **Ingestion pipeline** — "ingestion" means taking something in, like eating. "Pipeline"
   means a series of steps, one after another. So the ingestion pipeline is the code that
   takes events from outside the system and brings them in, step by step. It is the post
   office. The event generator creates the events (like people writing letters), and the
   ingestion pipeline collects them, checks them, stamps them with an arrival time, and
   files them in the right place.

So the envelope is the outside information — which event, what time, which order. The
payload is the inside information — the actual details of what happened.

**In one sentence:**

Each event has two parts: the payload and the envelope. The generator creates the event_id, and the ingestion pipeline is the code that picks up the events, reads them to find duplicates, rejects the duplicate events, and assigns the ingestion time in the envelope part. find duplicates, rejects the duplicate events, and assigns the ingestion time in the envelope part.
