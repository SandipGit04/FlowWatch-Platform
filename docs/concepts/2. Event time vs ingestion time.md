# Event Time vs Ingestion Time

**What problem does this solve?**

`event_time` tells us when something actually happened in the real world — the exact
moment. `ingestion_time` tells us when the system received it, which can be much later if
there was a signal problem or a technical glitch. Keeping them separate means the
analytics reflect when things really happened, not when they happened to arrive.

**What confused me at first:**

I was confused about whether the ingestion pipeline takes the events step by step — first
`order_created`, then `order_confirmed`, and so on — or whether it can take the events in
parallel. I also had no idea how the events would be arranged in the postbox.

**What made it click:**

**1. Why events arrive out of order in real life.** Ayan's order:

```
6:30 PM  order_created      ← phone has good signal, sends instantly
6:32 PM  order_confirmed    ← restaurant tablet, sends instantly
6:45 PM  rider_assigned     ← sends instantly
6:50 PM  rider_reached      ← rider in a basement, NO SIGNAL
7:00 PM  picked_up          ← still no signal
7:25 PM  delivered          ← signal comes back! Now the phone sends
                              rider_reached, picked_up, AND delivered
                              all at once
```

So the pipeline receives `delivered` at the same moment as `rider_reached`, even though
`rider_reached` happened 35 minutes earlier. This is normal, and it is exactly why
`event_time` is kept separate from `ingestion_time`. The story is told by `event_time` —
the ingestion order is meaningless.

**2. The postbox is a folder.** Events are not dumped into one giant folder. They are
sorted into folders by type and date:

```
data_lake/bronze/
│
├── event_type=order_created/
│   ├── event_date=2026-03-14/
│   │   ├── order_created_183000_8f3a21c9.json
│   │   └── order_created_183412_2b9d44a1.json
│   └── event_date=2026-03-15/
│       └── ...
│
├── event_type=order_confirmed/
│   └── event_date=2026-03-14/
│       └── ...
│
└── event_type=payment_event/
    └── event_date=2026-03-14/
        └── ...
```

**In one sentence:**
event_time is the exact moment when the event happens, and ingestion_time is the time when the pipeline picks up the event — whenever it becomes available, not based on order — and stamps that moment onto the event.
